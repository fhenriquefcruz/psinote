# Phase 5 — Versioned Documents

## ESTADO ANTERIOR

The document area mixed uploaded files and generated PDFs in the same generic workflow.

Document templates were unversioned JavaScript objects, the preview was only interpolated plain text, and saving a generated PDF did not preserve a reliable template/version provenance.

Some modalities that require specific professional contexts (assessment, expert consultation or multiprofessional authorship) were exposed through generic forms even though PsiNote did not model those underlying workflows.

## PROBLEMA

- no persisted draft lifecycle;
- no immutable issued-document boundary;
- no reliable template/version provenance;
- approximate preview instead of the real PDF;
- psychological document modalities mixed with administrative/consent material;
- unsafe generic forms for assessment-dependent documents;
- legacy template code could drift independently from the generated artifact.

## DECISÃO

Separate the concepts:

1. `document_drafts` — editable authoring state;
2. `documents(kind=generated,status=issued)` — immutable issued artifacts;
3. `documents(kind=attachment,status=stored)` — private external files;
4. code-versioned system templates;
5. future administrative/consent workflows remain separate from psychological document modalities.

The first enabled psychological templates are:
- Declaração;
- Relatório Psicológico.

Temporarily restricted:
- Atestado Psicológico;
- Laudo Psicológico;
- Relatório Multiprofissional;
- Parecer Psicológico.

Administrative/consent material is also not emitted through the psychological-document flow.

## BASE NORMATIVA USADA NO PRODUTO

The template taxonomy and safeguards were reviewed against:
- Resolução CFP nº 06/2019;
- Resolução CFP nº 06/2019 comentada;
- Manual Orientativo de Registro e Elaboração de Documentos Psicológicos, CFP, 2025.

The software does not claim automatic ethical/legal compliance. Professional judgment remains required for every issued document.

## IMPLEMENTAÇÃO

### Templates
- stable template IDs;
- explicit template version;
- family/type/availability metadata;
- per-template fields and conditional requirements;
- normative guidance and restriction reasons;
- shared structured render model.

### Declaração
- objective attendance/follow-up workflow;
- mandatory stated purpose;
- conditional time/follow-up fields;
- no symptom/state/diagnosis field exists in the template.

### Relatório Psicológico
- Identificação;
- Descrição da demanda;
- Procedimento;
- Análise;
- Conclusão;
- no automatic copying of session narrative.

### Authoring lifecycle
- save/resume draft;
- template and patient locked after first persisted draft;
- exact PDF preview generated by the same renderer used for issue;
- explicit confirmation before issue;
- issue metadata and draft closure written atomically in Firestore;
- issued document cannot be updated or deleted by browser clients.

### Storage
- private Firebase Storage path;
- no permanent public URL for new files;
- SHA-256 metadata;
- generated artifact and ordinary attachment share the same private-file boundary.

### UI
- dedicated document-authoring workspace;
- restricted templates visibly blocked with explanation;
- documents center with drafts, issued artifacts and attachments separated;
- visible issue/template version metadata.

## TESTES

Unit tests cover:
- enabled/restricted template catalog;
- version lookup;
- conditional declaration requirements;
- invalid attendance time;
- objective declaration rendering;
- psychological report structure;
- restricted template emission denial.

Firebase Rules tests cover:
- draft tenant isolation;
- patient/template/owner immutability;
- generated document requires paired draft transition;
- issued draft immutability;
- issued document immutability;
- attachment creation;
- cross-tenant patient-link denial.

## SEGURANÇA E PRIVACIDADE

- clinical/document body is not copied into operational activity logs;
- browser cannot hard-delete stored files or document metadata;
- document issue is append-only at the artifact level;
- template/version provenance is explicit;
- issuance requires professional identity fields in the UI;
- Storage remains private.

## RISCOS RESTANTES

- Storage upload and Firestore issue metadata cannot be a single cross-service transaction; an upload may become orphaned if Firestore commit fails and must be reconciled by a privileged maintenance workflow;
- legacy public Supabase URLs remain a migration risk;
- electronic signature/qualified signature is not implemented;
- delivery/receipt/protocol workflow is not implemented;
- atestado/laudo/parecer/multiprofessional workflows remain intentionally unavailable until their source processes are represented safely;
- custom organization templates require a future secured template registry.

## PRÓXIMA FASE

Global command/search architecture and then quality expansion (integration/E2E/accessibility/mobile/visual regression).
