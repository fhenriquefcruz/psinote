# PsiNote Product Vision

## Product promise

PsiNote should help a professional move from:

"I have appointments and scattered notes"

to:

"I immediately know what needs attention, I can understand each person's trajectory, record the work safely and find what I need without fighting the system."

## North-star experience

When opening PsiNote at the start of the day, the professional should be able to answer in seconds:

- Who am I seeing today?
- What is the next appointment?
- Which completed appointments still need a record?
- Which records/documents need attention?
- Where do I resume the context of a patient?
- Can I safely leave and return to a session draft?

## Product principles

### Work before metrics
Operational priorities precede charts.

### Patient/client context before navigation
The patient profile should gather trajectory and next actions.

### Narrative freedom with structured support
Professional documentation should support narrative writing without forcing a rigid medical checklist.

### Safe defaults
Private, tenant-scoped and reversible by default.

### Visible system state
Saving, loading, pending, archived and destructive states must be obvious.

### No silent automation of professional judgment
The system can organize and suggest, but the professional approves the official record.

### Mobile is a real work surface
Critical flows must remain usable at 375px, not merely responsive.

## Success indicators

Product indicators should focus on workflow completion rather than vanity metrics:
- completed appointment -> completed record conversion;
- time to open the correct patient;
- time to start/resume a session record;
- rate of recovered drafts;
- number of overdue documentation tasks;
- successful document retrieval;
- failed authorization attempts (security telemetry, without clinical content);
- accessibility/quality gate pass rate.
